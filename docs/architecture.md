# Architecture

## Overview

SpeakDataWith.com is a statically generated website. At build time, Astro
turns Markdown/MDX articles and Astro components into plain HTML, CSS, and a
minimal amount of client-side JavaScript. Cloudflare Pages serves the output
of `dist/` verbatim. There is no CMS, no database, and no server-side
runtime.

## Stack

| Concern | Choice | Notes |
| --- | --- | --- |
| Framework | Astro (static output) | Current stable major; pinned in `package.json` |
| Language | TypeScript, strict mode | `tsconfig.json` extends `astro/tsconfigs/strict` |
| Package manager | npm | `package-lock.json` is committed; CI uses `npm ci` |
| Content | Astro Content Collections | `articles` collection, defined in `src/content.config.ts` |
| Article format | Markdown (`.md`) | MDX (`.mdx`) only when an article embeds components |
| Styling | Single global stylesheet | `src/styles/global.css`, no CSS framework |
| Images | Astro asset pipeline (`astro:assets`) | Local files only, optimized at build time |
| Video | Click-to-load facade | `src/components/YouTubeFacade.astro`, `youtube-nocookie.com` |
| Validation | `npm run check` / `npm run build` | GitHub Actions workflow `.github/workflows/validate-site.yml` |
| Hosting | Cloudflare Pages | See `docs/cloudflare-pages-setup.md` |

## Deliberate exclusions

- **No UI framework** (React, Vue, Svelte): the site has no interactive
  application surface; Astro components cover everything.
- **No Tailwind CSS**: a single small stylesheet is sufficient and keeps the
  build dependency-free.
- **No headless CMS, no database**: articles are Markdown files in the
  repository; git history is the revision history.
- **No Cloudflare Workers / Pages Functions**: nothing requires server-side
  execution.
- **No client-side JavaScript libraries**: the only client-side script is
  the ~30-line click-to-load handler bundled with `YouTubeFacade.astro`.
- **No external image hosting, no own video hosting**: images are optimized
  from the repository; videos remain on YouTube behind the facade.
- **No comments, newsletter, analytics, or third-party scripts.**

## Rendering model

- `src/layouts/BaseLayout.astro` renders the HTML skeleton, canonical URL,
  meta description, Open Graph and Twitter card basics, the navigation, and
  the RSS autodiscovery link.
- `src/layouts/ArticleLayout.astro` renders article metadata (title,
  description, publication and update dates, pillars) and the optional
  repository, release, and evidence links.
- Pages:
  - `/` homepage with the latest published articles and an explicit empty
    state,
  - `/articles/` overview of published articles, newest first,
  - `/articles/<slug>/` article pages generated from the collection,
  - `/about/` technical placeholder,
  - `/rss.xml` RSS feed,
  - `sitemap-index.xml` / `sitemap-0.xml` generated by `@astrojs/sitemap`.

## Draft handling

Drafts (`draft: true` in the frontmatter) are filtered by
`src/utils/articles.ts::getPublishedArticles()`, which is the single source
for the homepage, the article overview, the RSS feed, and
`getStaticPaths()`. Draft articles therefore never produce a public page and
never appear in the RSS feed or the sitemap.

## Client-side JavaScript

The only client-side script is the one bundled with `YouTubeFacade.astro`.
It attaches click handlers to facade buttons and creates the YouTube iframe
(`https://www.youtube-nocookie.com/embed/`) only after an explicit user
interaction. Before that click, the page contains no iframe and makes no
request to YouTube. The video ID is validated against a strict character
allowlist before it is used in a URL.

## Supply chain

- `astro check && astro build` runs in CI (workflow `validate-site`, stable
  job name for use as a required status check).
- The workflow needs no secrets and has `permissions: contents: read`.
- Supplementary quality gates run from
  [quality-gates-toolkit](https://github.com/LuisArteaga/quality-gates-toolkit)
  (see `docs/quality-gates.md`).
- Action references are pinned to major versions; pinning them to full
  commit SHAs is a documented follow-up hardening step (see
  `docs/github-repository-settings.md`).
