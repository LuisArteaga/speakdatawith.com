# Architecture

## Overview

SpeakDataWith.com is a statically generated website. At build time, Astro
turns Markdown/MDX articles and Astro components into plain HTML, CSS, and a
minimal amount of client-side JavaScript. Cloudflare Pages serves the output
of `dist/` verbatim. There is no CMS, no database, and no server-side
runtime.

## Stack

| Concern | Choice | Notes |
| --- | --- | --- |
| Framework | Astro (static output) | Current stable major; pinned in `package.json` |
| Language | TypeScript, strict mode | `tsconfig.json` extends `astro/tsconfigs/strict`; pinned to 6.0.3 exactly (see below) |
| Package manager | npm | `package-lock.json` is committed; CI uses `npm ci` |
| Content | Astro Content Collections | `articles` collection, defined in `src/content.config.ts` |
| i18n | Astro i18n + local UI dictionaries | Locales `en`, `de`, `es` in `src/i18n/`; see `docs/multilingual-architecture.md` |
| Article format | Markdown (`.md`) | MDX (`.mdx`) only when an article embeds components |
| Styling | Single global stylesheet | `src/styles/global.css`, no CSS framework |
| Images | Astro asset pipeline (`astro:assets`) | Local files only, optimized at build time |
| Video | Click-to-load facade | `src/components/YouTubeFacade.astro`, `youtube-nocookie.com` |
| Unit tests | Vitest | Pure logic in `src/utils/` and the schema in `src/schemas/article.ts`, tests in `tests/` |
| Validation | `npm test` / `npm run validate` | GitHub Actions workflow `.github/workflows/validate-site.yml` |
| Hosting | Cloudflare Pages | See `docs/cloudflare-pages-setup.md` |

## Deliberate exclusions

- **No UI framework** (React, Vue, Svelte): the site has no interactive
  application surface; Astro components cover everything.
- **No Tailwind CSS**: a single small stylesheet is sufficient and keeps the
  build dependency-free.
- **No headless CMS, no database**: articles are Markdown files in the
  repository; git history is the revision history.
- **No Cloudflare Workers / Pages Functions**: nothing requires server-side
  execution.
- **No client-side JavaScript libraries**: the only client-side script is
  the ~30-line click-to-load handler bundled with `YouTubeFacade.astro`.
- **No external image hosting, no own video hosting**: images are optimized
  from the repository; videos remain on YouTube behind the facade.
- **No comments, newsletter, analytics, or third-party scripts.**

## Rendering model

- `src/layouts/BaseLayout.astro` renders the HTML skeleton, canonical URL,
  hreflang alternates when a localized page supplies them, meta
  description, Open Graph and Twitter card basics, the navigation, the
  RSS autodiscovery link, and (on localized pages) the language switcher.
- `src/layouts/ArticleLayout.astro` renders article metadata (title,
  description, publication and update dates, pillars) and the optional
  repository, release, and evidence links.
- Pages:
  - `/en/`, `/de/`, `/es/` language homepages with the latest published
    articles of that language and an explicit empty state; the root `/`
    redirects to `/en/` at the Cloudflare edge (`public/_redirects`),
  - `/en/articles/` (and `de`/`es`) overview of published articles,
    newest first,
  - `/en/articles/<slug>/` (and `de`/`es`) article pages generated from
    the collection,
  - `/about/` technical placeholder,
  - `/impressum/` and `/datenschutz/` legal placeholders with `noindex`
    and footer links, blocked for production until legally reviewed
    content replaces them (see `docs/cloudflare-pages-setup.md`),
  - `/404` not-found page (`404.html`, served automatically by
    Cloudflare Pages),
  - `/en/rss.xml`, `/de/rss.xml`, `/es/rss.xml` per-language RSS feeds;
    `/rss.xml` redirects to `/en/rss.xml` at the edge,
  - `sitemap-index.xml` / `sitemap-0.xml` generated by `@astrojs/sitemap`.

## Publication rules

An article is published only when it is intentionally released:
`src/utils/articles.ts::getPublishedArticles()` is the single publication
filter for the language homepages, the article overviews, the RSS feeds,
`getStaticPaths()`, hreflang clusters, and the language switcher. English
source articles are excluded when `draft: true` or when `publishedAt`
lies strictly in the future; translations additionally require
`translationStatus: "reviewed"`, a matching `sourceRevision`, and a
published English source. Excluded articles therefore never produce a
public page and never appear in an RSS feed or the sitemap.
The future-date rule is clock-injectable (`now` parameter) so it stays
unit-testable. The full translation publication model is described in
`docs/multilingual-architecture.md`.

## TypeScript 6.0.3 pin

`typescript` is pinned to exactly `6.0.3` (no caret). Astro's `astro
check` uses the compiler's programmatic API, which the TypeScript 7
native compiler no longer exposes; with `typescript@7` installed,
`astro check` fails. Once Astro supports the native compiler, the pin
can move.

## Client-side JavaScript

The only client-side script is the one bundled with `YouTubeFacade.astro`.
It attaches click handlers to facade buttons and creates the YouTube iframe
(`https://www.youtube-nocookie.com/embed/`) only after an explicit user
interaction. Before that click, the page contains no iframe and makes no
request to YouTube. The video ID is validated against a strict character
allowlist before it is used in a URL.

The facade also renders a plain link to the video's watch page on
`youtube.com` ("Watch this video on YouTube"), so the video stays reachable
when JavaScript is disabled. The embed and watch URLs are assembled by pure
helpers in `src/utils/video.ts` (`buildYouTubeEmbedUrl`, `buildYouTubeWatchUrl`),
which reject malformed video IDs instead of building a broken URL. The
post-click iframe is hardened with `loading="lazy"` and
`referrerpolicy="strict-origin-when-cross-origin"` (attributes defined by
`buildYouTubeEmbedAttributes`). When a Content Security Policy is introduced,
the `youtube-nocookie.com` frame host and the player's permission allow-list
(the `allow` attribute) are the reference points for the frame and
allow-list directives.

## Supply chain

- `npm run validate` runs in CI (workflow `validate-site`, stable job name
  for use as a required status check): `astro check` exactly once, then
  `astro build`, then the automated `dist/` leak check
  (`scripts/check-dist.mjs`) that fails when the build output would leak
  environment files, git metadata, docs, Markdown sources, or source maps.
- The workflow needs no secrets and has `permissions: contents: read`.
- Supplementary quality gates run from
  [quality-gates-toolkit](https://github.com/LuisArteaga/quality-gates-toolkit)
  (see `docs/quality-gates.md`).
- Action references are pinned to major versions; pinning them to full
  commit SHAs is a documented follow-up hardening step (see
  `docs/github-repository-settings.md`).
